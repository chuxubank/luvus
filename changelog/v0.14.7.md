Luvus v0.14.7 is a fork integration release that adds direct Kitty graphics placements from [#539](https://github.com/RizRiyz/luvus/pull/539). This replaces the Unicode-placeholder implementation removed in v0.14.6; it does not restore that old path. Existing settings and sessions remain compatible. The client protocol is now 24, so restart running servers after upgrading.

## Features

- **Terminal:** Unix thin clients display images only after the host explicitly accepts Kitty graphics and usable cell dimensions are known. Images are clipped to their pane, follow retained rows through scrolling and reflow, and are hidden while Luvus overlays cover the pane.
- **Multiple displays:** Each client has independent image ownership and placement state. Passive displays do not change the child application's cursor geometry.

## Fixes

- **Graphics:** Bound transfers, synchronized updates, image storage and frame uploads. Backpressure retries retain pending uploads, and image and placement IDs are retired without affecting other panes.
- **Terminal:** Recover unfinished synchronized updates through the existing timeout, and preserve image placement order across nested updates, wide-character reflow and tall images.
- **Tests:** Wait for an owner-only Unix socket before live conformance requests, avoiding the bind-before-permissions startup race without relaxing endpoint validation.

## Known limitations

- Kitty drawing is not advertised by Windows or the `--local` text renderer.
- Animation commands (`a=f`, `a=a`, `a=c`) are explicitly unsupported.
- Cell dimensions use ioctl first, then one bounded `CSI 16 t` query. Without a valid size, graphics remain disabled. Late replies do not restore support; reattach to try again. The current Crossterm parser can also consume an invalid byte in a malformed raw size reply before Luvus receives an input event.
- Physical Kitty-host visual verification has not been performed.

This tag is published from `chuxubank/luvus` `develop`; the upstream PR remains separate.
