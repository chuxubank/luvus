Luvus v0.14.8 is a fork integration release that improves the direct Kitty graphics implementation from [#539](https://github.com/RizRiyz/luvus/pull/539). Images are cropped around local overlays, and client-owned machine dialogs restore graphics through fresh, viewport-checked frames. Existing settings and snapshots remain compatible; the client protocol remains 24. Restart running servers after upgrading so both server and clients use the fixes.

## Improvements

- **Graphics:** Menus, submenus and toasts crop only the covered image area. Closing these server-rendered overlays restores retained pixels without retransmitting them; full-backdrop dialogs hide images conservatively.
- **Multiple displays:** Occlusion uses each client’s completed render and viewport. Cropping adds at most 32 extra placement rectangles per frame, with a bounded 64-region inventory and conservative fallback.

## Fixes

- **Machine dialogs:** Hide only placements actually painted by the client, retain image assets, and restore from a fresh endpoint-, boot-, ticket- and viewport-checked complete frame. Resizing refreshes the restoration ticket without extending its deadline, and cell-pixel changes are forwarded independently.
- **Recovery:** Failed or timed-out restoration returns input ownership to the active endpoint without painting stale queued frames. A fresh explicit preparation is required to restore the visual surface.
- **Clipping:** Pane boundaries and overlay fragments share offset-aware source coordinates, avoiding image jumps when an offset image scrolls beneath a menu.
- **Capabilities:** Child queries report only supported direct transfers and formats, with the requested quiet-response policy. Oversized chunked transfers preserve the originating image ID in errors and remain silent for q=2.
- **Image validation:** Reject malformed PNG containers, APNG and oversized images before storage or placement. Native dimensions are limited to 4096 pixels per axis, transmitted data and RGBA surfaces to 8 MiB, and PNG scanline storage to 8 MiB. Natural and explicit placement geometry share bounded cursor and lookback calculations.

## Known limitations

- Kitty drawing is available only to supported Unix thin clients, not Windows or the --local text renderer. Physical Kitty-host visual verification and local Windows hardware testing have not been performed.
- File/shared-memory transfers, compressed transfer data, animation commands and APNG are unsupported. PNG validation checks container structure, CRCs and allocation bounds without inflating IDAT; pixel-stream decoding remains the host terminal’s responsibility.
- Cell dimensions use ioctl first, then one bounded CSI 16 t query. Missing dimensions fail closed; late raw replies do not restore graphics through the current Crossterm path. Reattach to retry.
- Client-owned machine dialog closure uses the existing full-clear/replay contract and therefore reuploads image pixels, unlike ordinary server-rendered menu closure.

This release is published from chuxubank/luvus develop. It does not merge the upstream PR or include the uncommitted sidebar text-filter work.
