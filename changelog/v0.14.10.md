Luvus v0.14.10 is a fork integration release. It brings the review fixes made on [#540](https://github.com/RizRiyz/luvus/pull/540) and [#541](https://github.com/RizRiyz/luvus/pull/541) after v0.14.9. The client protocol stays 25, so a v0.14.9 client and server can still connect. Restart is not required for a protocol change.

## Improvements

- **Sidebar:** Clearing a FILES filter restores the saved file target with the visible row. A matching linked worktree keeps its parent workspace, while non-matching siblings still disappear. Canceling an ordinary FILES action menu no longer replaces the saved path when no filter was cleared. Dense path abbreviations can match later in a path, and sparse absolute-path alignments still do not.
- **Themes:** The `terminal` theme now paints with the host terminal's default color and ANSI slots instead of a probed RGB snapshot. Host colors still belong to the display that owns them. A display handoff keeps the newest color generation, and a clipboard receipt is delivered after a host-color update.
- **Input:** Late OSC 4, 10, and 11 replies from the host color query are consumed before they can become pane input, including when the next fragment arrives after the short prefix hold.

## Known limitations

- A Luvus pane does not yet repaint when the outer terminal changes its palette without a focus change. The `terminal` theme uses default and ANSI colors, but this WezTerm behavior is not fixed in this release. Real-time DEC 2031 notifications remain disabled because Crossterm 0.29 cannot deliver `CSI ?997` without swallowing later input.
- A program that subscribes to DEC 2031, including Pi's `light/dark` theme, still depends on the outer terminal sending that notification. Current WezTerm builds do not. Ghostty does. Luvus does not add a polling color query.
- Kitty drawing remains limited to supported Unix thin clients. Physical Kitty-host visual verification and local Windows hardware testing have not been performed for this release.

This release is published from chuxubank/luvus develop. It does not merge the upstream pull requests.
